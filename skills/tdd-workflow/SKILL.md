# Test-Driven Development Workflow

> **Size budget: 8 KB** — `token-budget.mjs --check`.

Use this skill when writing new features, fixing bugs, or refactoring code. Enforces test-driven development with canonical risk-appropriate coverage including unit, integration, and E2E tests.

## Working procedure

1. Establish the relevant mode and existing evidence; do not repeat completed intake.
2. Start with a failing test for a behavioral defect or substantive feature, then implement and refactor. Assert state and side effects, including failure paths. Preserve repository/user coverage policy; Go coverage measures statements, not branch coverage. Reversible low-impact prose/config edits need proportionate verification.
3. Read only the corresponding sections below before applying their examples.
4. Verify the result with meaningful positive, negative and failure controls. Record actual outcomes, limitations and next action.
